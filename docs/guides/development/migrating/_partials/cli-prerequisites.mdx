Install the [Clerk CLI](/docs/cli), sign in, and link the project directory you'll run the migration from to the Clerk application you're importing into:

```sh {{ filename: 'terminal' }}
npm install -g clerk
clerk auth login
clerk link
```

To skip `clerk auth login` and `clerk link`, set `CLERK_SECRET_KEY` to the [Secret Key](!secret-key) of the instance you're importing into, or pass it with `--secret-key`.

To skip the global install, replace `clerk` with `npx clerk@latest` in each command. To update an existing install, run `clerk update`.

`import` and `undo` target the linked application's development instance by default. Pass `--instance prod` or a full instance ID to choose another. With a Secret Key, the key picks the instance, so pass the production instance's key to import into production. For other ways to pick the instance and Secret Key, see [choose the destination instance](/docs/guides/development/migrating/how-the-cli-migrates-users#choose-the-destination-instance).

The CLI stores each run in `.clerk/migrate/<run_id>/` and adds `.clerk/` to `.gitignore`. To store runs elsewhere, see [command behavior](/docs/guides/development/migrating/how-the-cli-migrates-users#command-behavior).

> [!WARNING]
> New development instances have a [limit of 100 users](/docs/guides/development/managing-environments). Production instances have no user limit. Before creating users, the import checks a development instance's count against its limit and rejects the users past it. To rehearse with a larger export, import into development with `--allow-partial`, check the result, undo the run, then import everyone into production. See [instance user limits](/docs/guides/development/migrating/how-the-cli-migrates-users#instance-user-limits) for the commands, overrides, and fallback behavior.
