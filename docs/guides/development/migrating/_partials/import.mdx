Check the export against your Clerk instance first. A dry run writes nothing and skips the import's consent, legal acceptance, and reservation questions, so add `--skip-legal-checks` to preview importing users without [legal acceptance](/docs/guides/development/migrating/how-the-cli-migrates-users#legal-acceptance), or `--reserve-unverified` to preview reserving [unverified emails and phones](/docs/guides/development/migrating/how-the-cli-migrates-users#unverified-emails-and-phones):

```sh {{ filename: 'terminal' }}
clerk migrate import <export_run_id> --dry-run
```

The export recorded its source, so the import needs no `--source`. If the checks reject a user, fix the file or instance, or pass `--allow-partial` to import the users that pass. See [check before you import](/docs/guides/development/migrating/how-the-cli-migrates-users#check-before-you-import).

After the checks pass, rerun the same command with `--yes` instead of `--dry-run`, keeping the input and other flags. Leave off `--yes` to confirm at a prompt.

Use the import run's ID to check its results or undo it. To [continue an interrupted import](/docs/guides/development/migrating/how-the-cli-migrates-users#continue-an-interrupted-import), run the same command again.
