The `openInBrowser()` function opens a page of your web app in the device's default browser with the native app's user already signed in.

<Include src="_partials/expo/native-to-web/android-app-link-warning" />

For setup steps, see [Open your web app signed in from a native app](/docs/guides/development/native-to-web).

## Installation

On Android, this function requires `expo-intent-launcher` and `expo-application`. iOS doesn't need any extra packages.

```bash {{ filename: 'terminal' }}
npx expo install expo-intent-launcher expo-application
```

Without `expo-intent-launcher`, the function rejects with the `missing_dependency` error code on Android.

Then, import the function from the `@clerk/expo/native-to-web` subpath:

```tsx
import { openInBrowser } from '@clerk/expo/native-to-web'
```

## Usage

`openInBrowser()` has the following function signature:

```ts
function openInBrowser(params: OpenInBrowserParams): Promise<void>
```

### Parameters

`openInBrowser()` accepts the following parameters (`OpenInBrowserParams`):

<Properties>
  - `destination`
  - `string`

  The page to open, as an absolute URL. Outside development instances, it must use HTTPS. In production, it must share a root domain with one of your Clerk instance's domains.
</Properties>

### Returns

`openInBrowser()` returns a `Promise` that resolves after it starts opening the sign-in link. It doesn't wait for the web page to sign the user in, and if the sign-in fails on the web, your app isn't notified. See [how to handle a failed sign-in on the web](/docs/guides/development/native-to-web#handle-a-failed-sign-in-on-the-web).

The `Promise` rejects with a [`SessionTransferError`](/docs/reference/expo/is-session-transfer-error#sessiontransfererror) when Clerk can't create the link, or when opening the link fails before the `Promise` resolves.

Overlapping calls for the same `destination` share one link, so a double tap opens one browser tab.
