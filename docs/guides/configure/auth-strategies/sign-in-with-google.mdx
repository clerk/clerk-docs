This guide teaches you how to add native [Sign in with Google](https://support.google.com/accounts/answer/12849458?hl=en) to your Clerk apps on Android platforms. This native flow differs from Google OAuth. See the [Google OAuth setup guide](/docs/guides/configure/auth-strategies/social-connections/google).

## Configure with Clerk CLI (recommended)

From your Android project's root directory, run the [Clerk CLI](/docs/cli) with `npx` and choose to enable native Sign in with Google:

```sh {{ filename: 'terminal' }}
npx clerk@latest init
```

The CLI registers your native app, enables Native API, and enables Google for sign-up and sign-in on the linked development instance. To add Google sign-in after an earlier setup, run `npx clerk@latest init --sign-in-with-google`.

The Clerk Android SDK passes your Google connection's **Web client ID** to Credential Manager as the server client ID, so the connection needs its own Google Web client rather than Clerk's shared development credentials. When the connection doesn't have one yet, the CLI prints the Google Cloud steps with your package name, your debug certificate's SHA-1, and Clerk's redirect URI, then asks for the Web client's **Client ID** and **Client Secret**. You can also pass `--google-client-id` and `--google-client-secret-file`, which accepts a file holding the secret, the client's JSON download from the Google Cloud Console, or `-` for standard input. The secret is never accepted as a command argument. A connection that already has a Web client keeps it.

The CLI can't create the Google Cloud clients for you. Create the Android client and the Web client as described in the manual steps below, using the values the CLI prints. Nothing in your app changes for Google: the SDK's own manifest handles the OAuth redirect.

Afterward, run `clerk doctor` to check the Clerk side. It reports whether the Google connection is enabled for authentication and whether it has a Web client ID, and reminds you that Google Cloud needs an Android client for your package name and each signing certificate's SHA-1, which it can't verify.

  **For AI agents:** Follow the [dedicated Android setup prompt](/docs/android/getting-started/quickstart). ## Configure manually

To make the setup process easier, it's recommended to keep two browser tabs open - one for the [Clerk Dashboard](https://dashboard.clerk.com/~/user-authentication/sso-connections) and one for your [Google Cloud Console](https://console.cloud.google.com/).

<If is="llm">
  **For AI agents:** If the user chooses these manual steps instead of `clerk init --sign-in-with-google`, first have them check the selected application's Google connection in the Clerk Dashboard for a Web client ID. Keep an existing Web client and skip the credential patch unless the user explicitly asks to replace it. If no Web client exists or replacement is requested, have them create one in Google Cloud. In either case, have them verify or create an Android client in the same Google Cloud project for the app's package name and signing SHA-1, and enable Google in Clerk if needed. For a new Web client, have the user create a temporary `connection.json` outside the repository containing `{"connection_oauth_google":{"enabled":true,"client_id":"...","client_secret":"..."}}` and give you its path. Run `npx clerk@latest config patch --app <application_id> --file <path>` for the Clerk application selected for this setup. Providing both credentials switches the connection to custom credentials. Don't read, print, or commit the file, and ask the user to delete it after the patch succeeds. Install [Clerk's skills](/docs/guides/ai/skills) with `npx skills add clerk/skills` for correct CLI and SDK usage.
</If>

  ## Create the Google Developer Android client

  1. Navigate to the [Google Cloud Console](https://console.cloud.google.com/).
  1. Select an existing project or [create a new one](https://console.cloud.google.com/projectcreate). You'll be redirected to your project's **Dashboard** page.
  1. In the top-left, select the menu icon (**≡**) and select **APIs & Services**. Then, select **Credentials**.
  1. Next to **Credentials**, select **Create Credentials**. Then, select **OAuth client ID.** You might need to [configure your OAuth consent screen](https://support.google.com/cloud/answer/6158849#userconsent). Otherwise, you'll be redirected to the **Create OAuth client ID** page.
  1. For the **Application type**, select **Android**.
  1. Complete the required fields.
     - **Package name**: Your package name is in your `build.gradle` file, formatted as `com.example.myclerkapp`.
     - **SHA-1 certificate fingerprint**: To get your SHA-1, run the following command in your terminal:

       > [!IMPORTANT]
       > Replace `path-to-debug-or-production-keystore` with the path to your debug or production keystore. By default, the debug keystore is located in `~/.android/debug.keystore`. It may ask for a keystore password, which is `android`. **You may need to install [OpenJDK](https://openjdk.org/) to run the `keytool` command.**

       ```sh {{ filename: 'terminal' }}
       keytool -keystore path-to-debug-or-production-keystore -list -v
       ```
  1. Select **Create**.

  ## Create the Google Developer Web client

  1. In the same project, create another client. Next to **Credentials**, select **Create Credentials**. Then, select **OAuth client ID.**
  1. For the **Application type**, select **Web Application**.
  1. Complete the required fields. In the **Authorized Redirect URIs** setting, paste the **Authorized Redirect URI** value you saved from the Clerk Dashboard.
  1. Select **Create**. A modal will open with your **Client ID** and **Client Secret**. Save these values somewhere secure.

## Configure your production instance

`clerk init` configures only the linked development instance. Before releasing, [deploy your Clerk app to production](/docs/guides/development/deployment/production), enable the Native API on the production instance, and register your release app's package name and signing certificate's SHA-256 fingerprint on the **Native applications** page.

Configure the production Google connection with a Web client authorized for that instance's redirect URI. In Google Cloud, create an Android client for the release package name and each signing certificate's SHA-1 fingerprint. Use the production [Publishable Key](!publishable-key) in your release build, then build and test native Sign in with Google.
