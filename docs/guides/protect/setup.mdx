Clerk Protect runs inside Clerk's authentication flows. Applications that use Clerk's prebuilt components on current Clerk SDKs need no changes to their sign-up flow, though you might need to update your Content Security Policy. Before you enable a system protection, [check the requirements](#requirements). Then [enable the protections you need](#enable-protections) in the Clerk Dashboard and [test them in a development instance](#test-protections-before-production) before enabling them in production.

## Requirements

- **ClerkJS 6.39.0 or later.** Clerk's Core 3 SDKs, such as `@clerk/nextjs` 7 and `@clerk/react` 6, load the latest ClerkJS 6 automatically. Applications on older SDKs load ClerkJS 5 and need to [upgrade to Core 3](/docs/guides/development/upgrading/upgrade-guides/core-3). If your application bundles `@clerk/clerk-js` instead of loading it from Clerk, update the package. To see which version your site runs, open it in a browser and run `window.Clerk.version` in the developer console.
- **A Content Security Policy that allows Protect.** If your application sets a Content Security Policy, add the directives in [Configure Clerk Content-Security-Policy headers](/docs/guides/secure/best-practices/csp-headers). They cover Device Intelligence and challenges.
- **Support for challenges in custom sign-up flows.** If you enable a protection that can challenge, such as **Challenge suspicious sign-ups**, with a [custom sign-up flow](!custom-flow), your flow must be able to display a challenge. Clerk's prebuilt components do this automatically, but the Dashboard can't verify a custom flow. See [Handle sign-up challenges in your custom flow](/docs/guides/development/custom-flows/authentication/bot-sign-up-protection).

Sign-ups from native apps aren't challenged, but protections set to **Block** still apply to them. See [Native apps](/docs/guides/protect/system-protections/overview#native-apps).

For details on what each protection checks and requires, see [System protections](/docs/guides/protect/system-protections/overview).

## Enable protections

1. In the Clerk Dashboard, under **Protect**, navigate to the [**Protections**](https://dashboard.clerk.com/~/protect/rules) page.
1. Find the protection's row and check its **Status**.
   - If **Inactive**, select the settings icon at the end of its row. In the dialog, toggle on **Enable**, then select **Save**.
   - If **Active**, the protection is already enabled. To disable it, select the settings icon, toggle off **Enable**, then select **Save**.
   - If **Setup required**, select the settings icon and complete the setup. Clerk loads your application and checks its ClerkJS version and Content Security Policy against the [requirements](#requirements) before you can enable any protection. If the check can't reach your application, such as one running on your machine, confirm the requirements yourself and select **Bypass checks**. This can't be undone.
   - If the row shows a lock icon and no status, the protection requires the [Business plan](/docs/guides/protect/plans). Select the settings icon at the end of its row to upgrade, then toggle on **Enable** in the dialog and select **Save**.

If your application still uses legacy bot sign-up protection, update it first. The **Protections** page shows an **Update** banner instead of the steps above, and the update runs the same check, so the other protections are ready to enable once it's done. See [Update to Challenge suspicious sign-ups](/docs/guides/secure/legacy-bot-protection#update-to-challenge-suspicious-sign-ups).

## Test protections before production

Each instance has separate protection settings. Enable a protection in your [development instance](/docs/guides/development/managing-environments#development-instance), test a sign-up from a browser, and review any Protect events in [Application Logs](/docs/guides/dashboard/logs/application-logs#protect-events) before you enable it in production.

> [!IMPORTANT]
> Don't use a [Testing Token](/docs/guides/development/testing/overview#testing-tokens) for this test. Testing Tokens skip every protection that blocks or challenges, except [Require Device Intelligence checks](/docs/guides/protect/system-protections/require-device-intelligence).
