<If sdk="ios">
  > [!NOTE]
  > Enrollment requires biometrics to be available on the device. With the default policy, authentication can fall back to the device passcode. Pass `.biometryCurrentSet` as the `policy` when biometric enrollment changes should invalidate the key and every use must require the currently enrolled biometrics.
</If>

<If sdk="android">
  > [!NOTE]
  > Enrollment requires biometrics to be available on the device. With the default policy, authentication can fall back to the device PIN, pattern, or password on Android 11 (API level 30) and later. On Android 9 and 10, authentication remains biometric-only. Pass `BIOMETRY_CURRENT_SET` as the `policy` when biometric enrollment changes should invalidate the key and every use must require the currently enrolled biometrics.
</If>

<If sdk="expo">
  > [!NOTE]
  > Enrollment requires biometrics to be available on the device. The default policy, `'biometry_current_set'`, requires the currently enrolled biometrics and invalidates the private key when biometric enrollment changes. To allow fallback during sign-in, explicitly pass `'biometry_or_device_passcode'` as the `policy`. This allows the device passcode on iOS and the device PIN, pattern, or password on Android 11 (API level 30) and later. On Android 9 and 10, sign-in remains biometric-only.
  >
  > Credentials enrolled with a policy other than `'biometry_current_set'` cannot be used for biometric reverification. Keep the default policy if your app needs to reverify sessions with biometrics.
</If>
