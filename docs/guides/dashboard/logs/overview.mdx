The Clerk Dashboard offers three types of logs, each covering a different kind of activity:

| Log | Use it to investigate | Example events |
| - | - | - |
| [**Application Logs**](/docs/guides/dashboard/logs/application-logs) | Authentication and user activity within an instance | Sign-ins, sign-ups, sessions, user updates, and Organization changes |
| [**Email Logs**](/docs/guides/dashboard/logs/email-logs) | Delivery of transactional emails sent through Clerk | Accepted, delivered, deferred, bounced, and dropped emails |
| [**Admin Logs**](/docs/guides/dashboard/logs/admin-logs) | Configuration and administrative changes made from the Clerk Dashboard, [Backend API](/docs/reference/backend-api){{ target: '_blank' }}, or [Platform API](/docs/reference/platform-api){{ target: '_blank' }} | Instance settings, domains, secrets, Roles, Permissions, and integrations |

## Viewing and filtering logs

Each log page displays a reverse-chronological feed of events. The available filters differ by log type.

<Tabs items={["Application Logs", "Email Logs", "Admin Logs"]}>
  <Tab>
    You can filter Application Logs by:

    - **Event type**: The type of event (e.g., `user.created`, `sign_in.completed`). Supports trailing wildcards (e.g., `sign_in.*`).
    - **Actor**: The user or API key that triggered the event.
    - **Subject**: The ID of the resource being acted upon (e.g., a user ID or Organization ID).
    - **IP address**: The IP address the event originated from.
    - **Trace ID**: The distributed trace ID, for correlating events across systems.
    - **Device**: The device ID.
    - **Date range**: The time window to search.

    For a complete list of event types, see [Supported events](/docs/guides/dashboard/logs/application-logs#supported-events).
  </Tab>

  <Tab>
    You can filter Email Logs by:

    - **Event type**: The delivery outcome or interaction (e.g., `bounced`, `delivered`).
    - **Recipient**: The recipient's email address.
    - **IP address**: The IP address associated with the event.
    - **Message ID**: A specific message, to follow every event for it.
    - **Date range**: The time window to search.

    For a complete list of event types, see [Supported events](/docs/guides/dashboard/logs/email-logs#supported-events).
  </Tab>

  <Tab>
    You can filter Admin Logs by:

    - **Event type**: The type of event (e.g., `oauth_application.updated`, `domain.created`). Supports trailing wildcards (e.g., `oauth_application.*`).
    - **Instance**: The instance the action targeted.
    - **Application**: The application the action targeted.
    - **Actor**: The actor that triggered the event — a Dashboard user, an instance [Secret Key](!secret-key), or a Platform API access token.
    - **IP address**: The IP address the action originated from.
    - **Date range**: The time window to search.

    For a complete list of event types, see [Supported events](/docs/guides/dashboard/logs/admin-logs#supported-events).
  </Tab>
</Tabs>

## Log detail view

Select any log entry to view its full details, including:

- **Event metadata**: Fields such as event type and timestamp. Other fields vary by log type; for example, Email Logs include the recipient, message ID, and delivery status.
- **Payload**: Additional event data as a JSON object, when available.

## Plans and retention

Availability and log retention depend on your [plan](/pricing):

| Plan | Application Logs | Email Logs | Admin Logs |
| - | - | - | - |
| **Hobby** | 1 day | 1 day | Not available |
| **Pro** | 7 days | 7 days | Not available |
| **Business** | 30 days | 30 days | 30 days |
| **Enterprise** | Custom | Custom | Custom |

These retention periods apply to both **production** and **development** instances.

> [!IMPORTANT]
>
> Admin Logs record events starting August 24, 2026. Actions taken before this date are not available, regardless of your plan's retention period.
