> [!WARNING]
> On Android, the sign-in link opens in your app instead of the browser if your app has a verified App Link that matches it. The link's path is `/v1/session_transfers/redeem` on your [Frontend API URL](!frontend-api-url). The intent filter in the [passkeys setup](/docs/reference/expo/passkeys) matches every path on that host, so it matches the link, and the user isn't signed in on the web.
>
> To fix this, narrow the intent filter with `pathPrefix` or `pathPattern` to the paths that your app handles, or remove it if your app doesn't open links on that host. Keep your Android app registered on the [**Native applications**](https://dashboard.clerk.com/~/native-applications) page, which serves the `assetlinks.json` file.
