Clerk Protect uses [system protections](#available-system-protections) to block or challenge abusive sign-ups inside Clerk's authentication flows. You can turn on these protections from the [**Protections**](https://dashboard.clerk.com/~/protect/rules) page in the Clerk Dashboard, and Clerk enforces them. See [Set up Protect](/docs/guides/protect/setup) for more information.

Clerk Protect also includes features such as [Device Trust](/docs/guides/protect/device-trust), which can require a second factor during password sign-in.

## How system protections work

Most system protections check sign-ups and take one of three actions:

- **Allow**: The attempt continues.
- **Challenge**: The user completes a verification step, then continues. Most people pass it without doing anything. See [Challenges](/docs/guides/protect/challenges).
- **Block**: Clerk rejects the attempt.

Others lock an account, ask for a second factor, reject an email address, or limit how often something can be tried.

Each system protection decides when to challenge or block. [Protections that block or challenge](/docs/guides/protect/system-protections/overview#protections-that-block-or-challenge) explains when they check an attempt and what a blocked user sees. Every challenge and block appears as a Protect event in [Application Logs](/docs/guides/dashboard/logs/application-logs#protect-events). See [Monitoring and decision logs](/docs/guides/protect/monitoring).
