<If sdk="ios">
  > [!NOTE]
  > Enrollment requires biometrics to be available on the device. The default policy, `.biometryCurrentSet`, requires the currently enrolled biometrics and invalidates the private key when biometric enrollment changes. To allow the device passcode as a fallback during sign-in, pass `.biometryOrDevicePasscode` as the `policy`.
  >
  > To reverify sessions with biometrics, keep the default policy. Biometric reverification doesn't accept credentials enrolled with any other policy.
</If>

<If sdk="android">
  > [!NOTE]
  > Enrollment requires biometrics to be available on the device. The default policy, `BIOMETRY_CURRENT_SET`, requires the currently enrolled biometrics and invalidates the private key when biometric enrollment changes. To allow fallback during sign-in, pass `BIOMETRY_OR_DEVICE_PASSCODE` as the `policy`. This allows the device PIN, pattern, or password on Android 11 (API level 30) and later. On Android 9 and 10, sign-in remains biometric-only.
  >
  > To reverify sessions with biometrics, keep the default policy. Biometric reverification doesn't accept credentials enrolled with any other policy.
</If>

<If sdk="expo">
  > [!NOTE]
  > Enrollment requires biometrics to be available on the device. The default policy, `'biometry_current_set'`, requires the currently enrolled biometrics and invalidates the private key when biometric enrollment changes. To allow fallback during sign-in, explicitly pass `'biometry_or_device_passcode'` as the `policy`. This allows the device passcode on iOS and the device PIN, pattern, or password on Android 11 (API level 30) and later. On Android 9 and 10, sign-in remains biometric-only.
  >
  > To reverify sessions with biometrics, keep the default policy. Biometric reverification doesn't accept credentials enrolled with any other policy.
</If>
